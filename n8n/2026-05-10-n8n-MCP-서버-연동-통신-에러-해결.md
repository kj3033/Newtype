### Context
n8n 인스턴스 레벨(Instance-level) MCP 서버를 활용하여 외부 Antigravity 시스템과 연동하는 과정에서 'request terminated without response' 및 'Connection Interrupted' 오류가 지속적으로 발생함. ngrok 주소와 인증 토큰 등 필수 설정이 정상임에도 불구하고, MCP 프로토콜 통신 과정에서 데이터 전달이 원활하지 않은 문제가 확인됨.

### Core
이 문제는 전송 효율을 위해 발생하는 데이터 압축 방식과 클라이언트 파싱 간의 불일치로 인해 발생함. n8n과 ngrok 환경에서 Gzip/Deflate 압축이 적용될 때, 클라이언트가 이를 실시간으로 해제(Decompress)하지 못하고 연결을 강제 종료하는 것이 주원인임. 이를 해결하기 위해 HTTP 헤더에 압축을 사용하지 않도록 강제하는 `identity` 설정을 추가해야 함.

```json
{
  "n8n-native": {
    "type": "http",
    "serverUrl": "https://<your-ngrok-url>/mcp-server/http",
    "headers": {
      "Authorization": "Bearer <YOUR_TOKEN>",
      "Accept": "application/json, text/event-stream",
      "Accept-Encoding": "identity"
    }
  }
}
```

### Insight
`Accept-Encoding: identity`는 서버에게 데이터 압축이나 변형 없이 원본 그대로 전송할 것을 명시하는 표준 HTTP 헤더임. 이 설정을 통해 데이터 스트림이 가공되지 않은 텍스트 형태로 유지되어, 클라이언트 측의 불필요한 해제 오류를 방지함. 특히 ngrok와 같은 터널링 서비스나 불안정한 네트워크 환경에서 MCP(Model Context Protocol) 통신의 안정성을 확보하는 핵심적인 설정임. 시스템 간 연동 시 발생하는 통신 에러 해결 시, 성능을 위한 압축보다는 데이터 무결성과 안정성(identity)을 최우선으로 고려해야 함.
